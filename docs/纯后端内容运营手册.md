# 听会儿 App 纯后端内容运营手册

本文说明当前架构为什么这样设计，以及 App 发布以后，如何只操作 Supabase 和后台脚本来新增、更新、下线或回滚词书、发音、播客和 AI 总结。

## 1. 设计目标

这套架构遵循四条原则：

1. **客户端负责能力，后端负责内容。** App 内保留词书展示、播放、缓存、搜索和系统发音兜底等稳定能力；具体词书、MP3、播客、字幕和 AI 总结由后端提供。
2. **远端内容只能增强，不能破坏基础功能。** Supabase 不可用、网络异常或新数据损坏时，App 仍能读取安装包里的 A1、A2、B1、考研英语和雅思词书。
3. **先验证、再激活。** 新文件先上传到一个新版本路径，验证无误后才修改线上目录。上传本身不会让用户立即看到。
4. **所有版本都可回滚。** 不覆盖旧 JSON，尽量保留旧音频；线上目录只保存“当前应该使用哪个版本”的指针。

核心数据流：

```text
App 启动
  ├─ 立即读取安装包内置词书
  └─ 后台请求 Supabase word_books 目录
       ├─ 目录和 JSON 验证成功 → 使用远端版本并保存成功缓存
       ├─ 下载失败 → 使用相同版本的成功缓存
       └─ 无可用缓存 → 继续使用内置词书

播放发音
  ├─ 根据词书 audio_path_prefix 下载 Supabase MP3
  ├─ 下载成功 → 写入 TingHuiErAudioV4 缓存并播放
  ├─ 网络异常 → 尽量播放已有缓存
  └─ MP3 不存在或不可播放 → 使用 iOS 系统发音
```

## 2. 哪些更新不再需要发布 App

| 内容 | 后端来源 | 用户何时看到 |
|---|---|---|
| 新增或修改词书 | `word_books` + `word-book-content` Storage | 下次启动并加载词书 |
| 单词自然发音 | `learning-audio` Storage | 最迟在音频刷新周期后重新下载 |
| 播客节目和单集 | `podcasts`、`episodes` | 重新进入页面或下拉刷新 |
| 双语逐句字幕 | `episode_sentences` | 重新打开单集 |
| AI 总结与难词 | `episode_ai_insights`、`episode_difficult_words` | 重新打开单集 |

以下变化仍然需要发布 App：新增页面、改变交互、增加新的数据字段语义、改变播放器规则、增加新语种，或修复客户端代码缺陷。

## 3. 一次性初始化

### 3.1 环境变量

确认 `backend/.env` 中存在：

```dotenv
SUPABASE_URL=https://你的项目.supabase.co
SUPABASE_SERVICE_ROLE_KEY=你的服务端密钥
```

`SUPABASE_SERVICE_ROLE_KEY` 只能放在本地后台环境或可信服务器，禁止写入 iOS App、提交到公开仓库或发送给用户。

### 3.2 创建词书目录和 Storage bucket

在 Supabase Dashboard → SQL Editor 执行：

```text
supabase/sql/word_books_remote_catalog.sql
```

执行后会获得：

- `public.word_books`：词书发布目录。
- `word-book-content`：保存版本化词书 JSON 的公开 bucket。
- 只允许普通客户端读取已激活词书的 RLS 策略。

这一步只需执行一次。执行前，新版 App 仍会使用内置词书，不会白屏。

## 4. 词书 JSON 规范

词书是一个 JSON 数组。最小示例：

```json
[
  {
    "id": "001",
    "text": "example",
    "meaning": "例子；示例",
    "phonetic": "/ɪɡˈzɑːmpəl/",
    "example": "This is an example.",
    "exampleZh": "这是一个例子。"
  }
]
```

必要字段：

- `id`：本词书内唯一且长期稳定；发布后不要随意修改，否则收藏和学习进度可能无法定位。
- `text`：需要展示和朗读的单词。
- `meaning`：默认释义。

可选字段包括 `phonetic`、`example`、`exampleZh`、`exampleEn`、`audioFileName`、`article`、`meaningZh`、`meaningEn` 和 `source`。

自动安全限制：

- 文件必须是有效 JSON 数组。
- 1～100,000 个单词。
- 文件不超过 25 MB。
- `id` 和 `text` 不得为空。
- 同一本词书不能出现重复 `id`。

## 5. 新增一本词书

假设要新增英语六级词书：

```text
book-id: CET6
title: 大学英语六级
language: english
content-version: 2026-10-21-v1
audio-path-prefix: v2/words/en-us/cet6
```

### 第一步：本地验证，不上传

```bash
backend/.venv/bin/python backend/scripts/publish_word_book.py \
  --book-id CET6 \
  --title "大学英语六级" \
  --language english \
  --source backend/data/CET6.json \
  --content-version 2026-10-21-v1 \
  --audio-path-prefix v2/words/en-us/cet6 \
  --sort-order 30 \
  --dry-run
```

必须看到 `validated words JSON`，且命令正常退出后才能继续。

### 第二步：上传候选版本，不影响线上

执行同一命令，删除 `--dry-run`，但暂时不要增加 `--activate`：

```bash
backend/.venv/bin/python backend/scripts/publish_word_book.py \
  --book-id CET6 \
  --title "大学英语六级" \
  --language english \
  --source backend/data/CET6.json \
  --content-version 2026-10-21-v1 \
  --audio-path-prefix v2/words/en-us/cet6 \
  --sort-order 30
```

脚本会上传并重新下载核对 SHA-256，但不会修改线上 `word_books` 目录。

### 第三步：人工验收

在 Supabase Dashboard → Storage → `word-book-content` 检查：

```text
books/CET6/2026-10-21-v1.json
```

同时抽查：

- 单词、音标、中文释义和例句显示正常。
- `audio_path_prefix` 下存在对应 MP3，或确认允许暂时使用系统音。
- `book-id` 没有与现有词书重复。
- 语言选择正确：`english` 或 `german`。

### 第四步：激活上线

重新执行第二步命令，并在末尾加入：

```bash
--activate
```

激活后，新版 App 会自动发现 CET6，不需要重新打包。

## 6. 更新已有词书

更新时必须遵守：

- 保持原 `book-id`，例如始终使用 `CET6`。
- 使用新的 `content-version`，例如从 `2026-10-21-v1` 升到 `2026-11-03-v2`。
- 不要覆盖旧版本 JSON。
- 尽量保留已有单词的 `id`。

流程仍是：`--dry-run` → 上传但不激活 → 人工验收 → `--activate`。

客户端只有在远端 JSON 完整下载并通过校验后才替换当前内容。如果新文件损坏，用户继续使用成功缓存或内置版本。

## 7. 下线和回滚词书

### 下线远端词书

在 Supabase Table Editor → `word_books` 中将目标行：

```text
is_active = false
```

远端新增词书将不再显示。A1、A2、B1、考研和雅思是安装包内置兜底，即使对应远端行停用，也仍会显示内置版本。

### 回滚

不要删除当前错误版本。将 `word_books` 行中的下列字段指回已经验证的旧版本：

- `content_version`
- `data_url`
- `audio_path_prefix`

确认 `is_active = true`。用户下次重新加载词书时会恢复旧版本。

## 8. 新增或更新自然发音

### 路径约定

```text
德语：v2/words/de-de/<book-id 小写>/<文件名>.mp3
英语：v2/words/en-us/<book-id 小写>/<文件名>.mp3
中文释义：meanings/zh/<哈希文件名>.mp3
英文释义：meanings/en/<哈希文件名>.mp3
```

`word_books.audio_path_prefix` 填目录，不包含最后的 MP3 文件名。

### 生成和上传

现有内置词书可以直接指定 `--word-book`。新增加的远端词书不在脚本的内置名单中，应提供生成清单。例如 `backend/reports/audio/cet6_manifest.json`：

```json
[
  {
    "word": "example",
    "text": "example",
    "language": "en-US",
    "target_path": "v2/words/en-us/cet6/example_001.mp3"
  }
]
```

先少量生成并试听：

```bash
backend/.venv/bin/python backend/scripts/generate_word_audio_replacements.py \
  --manifest backend/reports/audio/cet6_manifest.json \
  --provider azure --limit 10
```

先预览上传：

```bash
backend/.venv/bin/python backend/scripts/upload_learning_audio.py --dry-run
```

上传缺失文件：

```bash
backend/.venv/bin/python backend/scripts/upload_learning_audio.py --list-first
```

验证公开访问：

```bash
backend/.venv/bin/python backend/scripts/verify_learning_audio.py \
  --source backend/generated/learning-audio
```

### 修复一个错误音频

确认本地新 MP3 已经人工试听通过后，才允许覆盖：

```bash
backend/.venv/bin/python backend/scripts/upload_learning_audio.py \
  --only-list backend/reports/audio/approved_replacements.txt \
  --overwrite
```

覆盖属于高风险操作。列表中只放已确认的问题对象，禁止用宽泛目录批量覆盖。App 会定时刷新远端音频；网络或新文件异常时会尝试旧缓存，最终使用系统音兜底。

## 9. 新增和更新播客

播客已完全采用后端内容模式。推荐流程：

```text
同步 RSS
  → 获取或生成字幕
  → 翻译
  → 生成 AI 总结和难词
  → 自动质检
  → 人工试听抽查
  → 发布
```

处理某个已配置来源的最新 5 集：

```bash
backend/.venv/bin/python backend/scripts/process_podcast_content.py \
  --source <source_key> --limit 5
```

查看审核候选：

```bash
backend/.venv/bin/python backend/scripts/review_podcast_content.py --limit 20
```

人工确认后发布最新一集：

```bash
backend/.venv/bin/python backend/scripts/publish_latest_podcast.py \
  --podcast-name "节目名称" \
  --latest 1 \
  --confirm-reviewed
```

App 只展示：

```text
podcasts.is_active = true
podcasts.rights_status = approved
episodes.editorial_status = published
episodes.transcript_status = ready
```

因此后台导入或处理中间失败不会直接污染用户页面。

## 10. 更新 AI 总结和难词

为某个节目生成缺失内容：

```bash
backend/.venv/bin/python backend/scripts/generate_podcast_ai_insights.py \
  --podcast-name "节目名称" --limit 10
```

需要重新生成已有结果时，明确使用：

```bash
backend/.venv/bin/python backend/scripts/generate_podcast_ai_insights.py \
  --podcast-name "节目名称" --limit 10 --force
```

`--force` 会覆盖已有 AI 内容，使用前应先确认模型、提示词和样本输出。App 会从 `episode_ai_insights` 和 `episode_difficult_words` 动态读取结果。

## 11. 发布前检查清单

### 词书

- [ ] 使用了稳定且唯一的 `book-id`。
- [ ] 使用了新的 `content-version`。
- [ ] `--dry-run` 通过。
- [ ] 候选文件已经上传但尚未激活。
- [ ] 随机抽查单词、释义、音标和例句。
- [ ] 抽查英语或德语发音及中文释义发音。
- [ ] 最后才使用 `--activate`。

### 播客

- [ ] 音频完整且可拖动。
- [ ] 字幕时间轴与声音基本一致。
- [ ] 中英文内容没有明显错位。
- [ ] AI 总结和难词经过抽查。
- [ ] 权利状态允许展示。
- [ ] 验证通过后才发布。

### 音频覆盖

- [ ] 已定位到准确的 Supabase 对象路径。
- [ ] 新 MP3 已在本地完整试听。
- [ ] 使用精确名单而不是整个 bucket。
- [ ] 覆盖后运行公开访问验证。
- [ ] 在真机上重新进入词书并试听。

## 12. 故障判断

### 新词书没有出现

依次检查：

1. App 是否为包含远端词书能力的新版本。
2. `word_books.is_active` 是否为 `true`。
3. `language` 是否为 `english` 或 `german`。
4. `data_url` 是否是可公开访问的 HTTPS 地址。
5. JSON 是否符合字段、大小和唯一 ID 限制。
6. 退出并重新进入 App，让词书目录重新加载。

### 仍然播放系统音

这通常表示对应 MP3 没有成功下载或无法播放，检查：

1. `audio_path_prefix` 是否与 Storage 实际目录一致。
2. 文件名是否与客户端生成规则一致。
3. URL 是否返回 HTTP 200，而不是 404、HTML 或权限错误。
4. MP3 是否超过最小有效大小且能被系统播放器解码。
5. 是否等待了缓存刷新周期，或使用新版本路径发布。

### 后端故障是否会影响旧功能

- `word_books` 表不存在或请求失败：继续显示内置词书。
- 新 JSON 损坏：不替换旧数据。
- 网络断开：读取成功缓存或内置数据。
- MP3 下载失败：播放缓存；没有缓存时使用系统音。
- 播客接口失败：页面显示重试入口，不影响词书学习。
