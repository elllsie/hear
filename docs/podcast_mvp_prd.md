# 「听会儿」英语 Podcast 学习闭环 PRD（MVP）

> 文档版本：v1.0  
> 日期：2026-10-02  
> 目标：验证用户是否愿意每天打开 App 听 10 分钟英语，并把真实语境中的生词带回单词复习系统。  
> 产品原则：小步验证；Podcast 是输入，不是第二个产品；先保证“听 → 遇 → 收 → 再听”闭环，不追求内容数量。

---

## 0. 现有项目判断与设计前提

现有 iOS 工程是 SwiftUI App，已经具备登录、游客模式、词书选择、单词播放、学习进度、收藏及 Supabase 云同步。词书来自本地 JSON；云端收藏目前只保存 `book_id + word_id`。

MVP 应直接复用：

- Supabase Auth 与现有游客/登录逻辑；
- 单词发音和连续播放能力；
- 本地优先、登录后同步的进度方式；
- 现有深色视觉语言。

开发前需修正一个概念：当前 `LearningLanguage` 的 `.english/.chinese` 实际控制释义与界面语言，并非“英语/德语”的学习语言。建议拆成：

- `StudyLanguage`: `english | german`
- `ExplanationLanguage`: `chinese | english`

Podcast 只在 `StudyLanguage == english` 时出现；German 保持当前词书学习路径。

# 一、产品定位

## 1.1 一句话定位

**听会儿是一款把英文 Podcast 中“没听懂的词”，自动带回真实语境反复听懂的声音学习 App。**

内部更短表达：**从听见，到听懂。**

## 1.2 用户核心价值

用户不需要在“听内容”和“背单词”之间切换：听到陌生表达时点一下即可理解并收藏；第二天先听原声再复习单词，最终回到原节目验证自己是否真正听懂。

价值不是“收藏更多词”，而是形成四种心理反馈：

- **即时反馈**：点词即懂，不因查词离开播放场景。
- **情境记忆**：单词连同说话人的声音、原句和主题一起被记住。
- **可见成就**：用户看到“昨天没听懂，今天听懂了”，而非只看到背了多少词。
- **低启动成本**：每天只需完成一段 5–10 分钟内容和少量真实生词复习。

## 1.3 与普通 Podcast App 的区别

普通 Podcast App 优化“发现、订阅和连续消费”；听会儿优化“听懂”。差异点是：

- 字幕按句同步，英文词可直接点击；
- 解释、原句、原声在同一播放上下文中完成；
- 生词进入既有单词系统，并保留节目、句子、时间点；
- 复习后可一键回听原句或回到节目，不让收藏成为“单词坟场”。

## 1.4 与普通背单词 App 的区别

普通背词从词表出发，语境多为人工例句；听会儿从用户真实遇到的内容出发。每个收藏词都回答三个问题：我在哪里听到、当时那句话是什么、现在能不能听懂。

## 1.5 用户每天愿意打开的理由

首页只给三个明确动作：

1. **继续昨天的 10 分钟**：减少内容选择疲劳；
2. **复习昨天遇到的词**：利用时间接近性形成记忆；
3. **再次挑战原声**：获得“这次我听懂了”的即时奖励。

不以连续打卡或排行榜施压。MVP 用“今日听了 X 分钟、听懂了 X 个昨日生词”表达温和成就感。

# 二、MVP 产品范围

## 2.1 第一版本必须做

### 内容与首页

- English 首页：今日推荐 1 条、继续收听、待复习词数、近 7 天听力分钟数。
- 精选 Podcast 列表：人工上架，按难度和主题浏览；不做搜索。
- 节目详情最小信息：标题、简介、来源、难度、时长、主题、版权/原始链接。

### 播放与字幕

- 单集在线播放、暂停、前后 15 秒、进度拖动、0.75/1.0/1.25 倍速。
- 锁屏/后台播放和系统 Now Playing 基础支持。
- 英文字幕按句同步；当前句高亮并自动滚动。
- 中文翻译可整页显示/隐藏，默认显示状态由用户上次选择决定。
- 点英文词弹出词卡；播放继续暂停由用户选择，MVP 默认自动暂停。

### 查词、收藏与复习闭环

- 词卡：词形、规范词元、音标、中文释义、原句、单词发音、收藏按钮。
- 收藏时记录节目、单集、句子、音频时间点及原始词形。
- “我的单词”区分“来自 Podcast”和“来自词书”，支持按最近收藏查看。
- Podcast 生词复习卡包含原句和“播放原声句”按钮。
- 复习结束展示“回到原节目，再听一次”按钮。

### 数据与最小运营

- 保存单集收听进度和完成状态。
- 登录用户云同步收藏及进度；游客可本地体验，收藏时沿用现有登录提示策略。
- 管理侧第一版可直接使用 Supabase Table Editor + Python 导入脚本，不开发 CMS。
- 基础埋点：曝光、开始播放、10 分钟收听、点词、收藏、原句回放、次日复习、回听节目。

## 2.2 第一版本明确不做

- AI 聊天、AI 老师、口语对练；
- 社区、评论、排行榜、好友关系；
- 复杂学习计划、考试体系、积分商城；
- 用户上传音频/RSS/字幕；
- 全网搜索、站内全文搜索；
- 订阅节目、个性化推荐算法、无限信息流；
- 离线下载、CarPlay、视频 Podcast、逐字卡拉 OK 字幕；
- 自动生成任意节目全文稿；
- 多义词复杂消歧、短语任意框选、语法树解析；
- 德语 Podcast；
- 独立运营后台。

## 2.3 后续规划边界

- V2：RSS 半自动入库、复习调度、短语收藏、下载、内容偏好。
- V3：在版权和质量可控的前提下，AI 个性解释/测验/复述反馈与有限个性化推荐。

# 三、信息架构

## 3.1 顶层结构

```text
启动
├─ 登录 / 注册 / 游客体验
└─ 选择学习语言
   ├─ English
   │  └─ Tab Bar
   │     ├─ 今日
   │     ├─ 精选
   │     ├─ 单词
   │     └─ 我的
   └─ Deutsch
      └─ 保持现有词书 → 播放设置 → 单词播放 → 我的
```

英文路径不是“词书 App + Podcast App”的并列组合。四个页面分别承担一个学习闭环阶段：

| 页面 | 核心作用 | 不承担 |
|---|---|---|
| 今日 | 决定今天听什么、先复习什么，并恢复未完成任务 | 海量内容发现 |
| 精选 | 从有限内容中选一集适合学习的节目 | 订阅、榜单、全网搜索 |
| 单词 | 复习从词书或 Podcast 遇到的词，并回听原声 | 重型词典 |
| 我的 | 账号、学习语言、解释语言、播放偏好、数据概览 | 社交身份 |

播放页是从“今日/精选/单词原节目”进入的沉浸页面，不占一个 Tab。

## 3.2 页面层级

```text
今日
├─ 今日推荐卡 → Episode 播放页
├─ 继续收听 → Episode 播放页（恢复进度）
└─ 昨日新词 → Podcast 复习队列
                 ├─ 原声句播放
                 └─ 回到 Episode 播放页（定位原句）

精选
├─ 难度筛选（A2/B1/B2）
├─ 主题筛选（生活/文化/科技/职场）
└─ Episode 卡 → 播放页

单词
├─ 待复习
├─ 来自 Podcast
├─ 来自词书
└─ 单词详情 → 来源节目 / 原句 / 原声

我的
├─ 学习数据
├─ 学习语言
├─ 解释语言
├─ 播放与字幕偏好
└─ 账号与数据
```

# 四、核心用户流程

## 流程 1：新用户首次打开到第一次听 Podcast

```text
启动 → 继续体验/注册登录 → 选择学习语言 English
→ 选择大致水平（A2 / B1 / B2，可跳过，默认 B1）
→ English 今日页
→ 今日推荐卡（默认 5–10 分钟）
→ 点击“开始听”
→ 首次浮层提示：点字幕里的词即可查看并收藏
→ 播放页，从头开始播放
```

关键设计：不先要求用户选择兴趣、订阅节目或制定计划。首次价值时刻必须在 60 秒内到达播放。

若选择 Deutsch：直接进入原有词书页，不出现 Podcast 入口。

## 流程 2：听 Podcast 时发现陌生词

```text
当前句随音频高亮
→ 用户点击英文词
→ 播放自动暂停，底部词卡弹出
→ 显示词 / 音标 / 中文释义 / 完整原句
→ 可点“发音”听单词音
→ 点“收藏”
→ 按钮变为“已收藏”，轻提示“已加入单词 · 保留这句原声”
→ 下滑关闭词卡或点“继续播放”
→ 回到原位置继续
```

异常分支：

- 未登录：先本地收藏；当用户访问跨设备同步或收藏达到 3 个时提示登录，避免首次查词被登录墙打断。
- 词典无结果：展示原始词形与原句，允许“仅收藏原句”，运营端补词；MVP 不调用聊天模型临时编造释义。
- 同一词重复收藏：不新增重复主记录，只追加/保留新的 `favorite_word_source` 语境。

## 流程 3：第二天复习昨日收藏词

```text
今日页出现“昨天遇到的 5 个词”
→ 点击“听听还记得吗”
→ 先播放 3–8 秒原声片段，字幕暂时隐藏目标词释义
→ 用户点“认识 / 再听一次 / 不记得”
→ 揭示单词、释义、原句和来源节目
→ 完成当日队列
→ 结果页：“昨天没听清的 5 个词，今天已听懂 4 个”
→ CTA“回到原节目验证一下”
→ 播放页定位到首个收藏语境
```

“昨天听过 → 今天再次遇见”通过三个元素显性表达：来源封面、相对日期“昨天收藏”、原声波形/播放按钮。成就口径用“听懂”而不是“背完”。

# 五、UI 界面设计

## 5.1 English 首页（今日）

### 页面布局

```text
┌─────────────────────────┐
│ 早上好，今天听 10 分钟       │
│ 连续学习弱提示 · 本周 32 分钟  │
├─────────────────────────┤
│ [大封面] 今日精选             │
│ Why We Need Small Talk       │
│ B1 · 8 min · 生活             │
│ [开始听 / 继续听 04:12]        │
├─────────────────────────┤
│ 昨天遇到的词          5 个      │
│ “听听还记得吗” [开始复习]       │
├─────────────────────────┤
│ 本周进度  32 / 70 分钟          │
│ 4 天有收听 · 听懂 12 个语境词    │
└─────────────────────────┘
 今日   精选   单词   我的
```

### 组件与交互

- `DailyHeroCard`：全页最强视觉，只推荐一集；主按钮面积至少 48pt 高。
- `ResumeState`：有未完成单集时，“继续听”优先于新推荐。
- `ReviewCard`：仅在有到期词时出现；显示来源封面堆叠而非单词列表。
- `WeeklyProgress`：一条轻量进度条，不做复杂图表；点击进入我的数据。
- 下拉刷新内容；骨架屏代替全屏转圈；错误时保留已缓存推荐。

## 5.2 Podcast 精选列表页

不展示订阅 feed，不模仿 Spotify。页面标题建议直接使用“适合你现在听的”。

### 布局

- 顶部：难度 segmented control（全部/A2/B1/B2）。
- 第二行：横向主题 chips（生活、文化、科技、职场）。
- 下方：运营排序的单列 Episode 卡片，每次首屏 6–10 条。

### Episode 卡片

- 左侧 88×88 封面；右侧标题最多两行。
- 元信息：`B1 · 8 分钟 · 慢速清晰`。
- 主题标签最多 2 个。
- 一句学习理由，如“日常寒暄高频表达”。
- 已听过显示进度条；已完成显示“已听懂”弱状态。
- 整卡点击进入播放页；不放收藏节目、下载或更多菜单。

## 5.3 Podcast 播放页（核心）

### 页面结构

```text
┌────────────────────────────┐
│ ‹  Episode title       ···  │
│ [64×64 cover] 节目名 · B1    │
├────────────────────────────┤
│           04:12 / 08:30     │
│ ─────────●───────────────    │
│ 0.75x   ↺15   [暂停]   15↻   │
├────────────────────────────┤
│ [EN/中译开关]  点词可收藏      │
│                            │
│ 前一句（弱化）               │
│ We often underestimate     │
│ how much small talk helps. │ ← 当前句高亮
│ 我们常常低估闲聊的作用。       │
│                            │
│ 后一句（弱化）               │
└────────────────────────────┘
```

### 核心规则

- 当前句背景使用品牌色 8–12% 透明度，左侧加 3pt 指示条；不能只靠颜色表达。
- 当前句保持在视口上半部；用户手动滚动后暂停自动滚动，出现“回到当前句”浮动按钮。
- 字幕按“句”同步，不要求逐词时间戳；句级同步可显著降低内容生产成本。
- 英文文本按 token 渲染为可点击词；标点不可点。点击后自动暂停并提供轻触反馈。
- 中文翻译位于英文句下方，字号小一级、对比度降低；可全局隐藏。
- 拖动进度时立刻定位对应句；点击任意字幕句将音频跳至 `start_ms`。
- 退出时保存进度；再次进入展示“从 04:12 继续 / 从头播放”。

### 点词底部词卡

建议使用 `presentationDetents([.medium, .large])`：

```text
┌────────────────────────────┐
│ underestimate       /ˌʌndər.../ │
│ 低估                       🔊 │
│                              │
│ 原句                          │
│ We often underestimate how… │
│ [▶ 播放这句原声]              │
│ 来源：Why We Need Small Talk │
│                              │
│ [☆ 收藏到我的单词]            │
│ [继续播放]                    │
└────────────────────────────┘
```

- 收藏主按钮完成后变为“✓ 已收藏”；关闭词卡后保持当前句位置。
- “播放这句原声”播放 `[start_ms - 300, end_ms + 300]`，结束后保持暂停。
- 第一次收藏只显示一次微文案：“明天会用这句原声帮你复习”。
- 长按或多义词切换延后；MVP 取内容运营预先审核的当前语境义项。

## 5.4 我的单词

### 页面结构

- 顶部：`待复习 N` 主卡，按钮“开始听词复习”。
- 筛选：`全部 | Podcast | 词书`。
- 默认按最近遇到排序；MVP 不做复杂排序。
- Podcast 单词卡：单词、中文义、原句一行、来源封面/标题、收藏日期、原声播放键。
- 词书单词保持现有展示和播放逻辑。

### Podcast 单词详情

- 单词 + 音标 + 释义；
- “你在这里遇到它”：完整原句与中文句译；
- 原句音频按钮；
- 节目封面、标题、时间点；
- CTA：“从这句话继续听”；
- 取消收藏置于次级菜单，并明确仅删除收藏，不删除词典词。

# 六、MVP 数据模型

## 6.1 关系概览

```text
Podcast 1 ── N Episode 1 ── N Sentence
                         │
                         └── N FavoriteWordSource N ── 1 UserFavoriteWord N ── 1 Word

User 1 ── N EpisodeProgress N ── 1 Episode
User 1 ── N UserFavoriteWord
```

题目指定的四张新增表不足以优雅表达“同一词在多个语境出现”以及收听进度，因此建议增加两个轻量表：`favorite_word_sources` 与 `episode_progress`。若必须极限压缩，也可把来源字段直接放进 `user_favorite_words`，但会丢失多语境能力。

## 6.2 字段设计

### `words`（已有，建议云端规范化）

| 字段 | 类型 | 约束/说明 |
|---|---|---|
| id | uuid/text | PK；可兼容现有字符串 ID |
| language | text | `en/de` |
| lemma | text | 规范词元，小写；如 `underestimate` |
| display_text | text | 展示词形 |
| phonetic | text nullable | IPA |
| meaning_zh | text | MVP 中文释义 |
| meaning_en | text nullable | 可复用现有英文释义 |
| audio_url | text nullable | 单词发音 |
| created_at | timestamptz | 审计字段 |

唯一索引建议：`(language, lemma)`。现有本地词书可继续保留，Podcast 词典应优先云端化，避免随 App 发版更新。

### `podcasts`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | uuid | PK |
| title | text | 节目名 |
| publisher | text | 出品方 |
| description | text | 简介 |
| artwork_url | text | 封面 |
| rss_url | text nullable | V2 使用 |
| website_url | text nullable | 原站链接 |
| language | text | MVP 固定 `en` |
| rights_note | text | 授权/使用依据记录 |
| status | text | `draft/published/archived` |
| created_at, updated_at | timestamptz | 审计 |

### `episodes`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | uuid | PK |
| podcast_id | uuid | FK → podcasts |
| guid | text nullable | RSS 去重键 |
| title | text | 单集标题 |
| summary | text | 学习向简介 |
| audio_url | text | HTTPS 音频地址 |
| artwork_url | text nullable | 无则继承节目封面 |
| source_url | text | 原始页面 |
| duration_ms | integer | 时长 |
| level | text | `A2/B1/B2` |
| speech_rate_wpm | integer nullable | 人工/脚本测得 |

3. iOS 过渡一个版本双读：新版优先，旧版作为兜底；

# 七、内容运营方案

## 7.1 第一阶段：人工精选

### 寻找候选内容

- Apple Podcasts/Spotify 等榜单只作为发现线索，不直接抓取或转载；
- 优先选择官方明确提供 RSS、音频和 transcript 的英语学习/知识类节目；
- 关注公共媒体、教育机构、独立创作者的短节目；
- 记录来源页、RSS、版权条款、是否允许嵌入/缓存/改编字幕。

热门不等于适合学习。MVP 内容池建议仅 20–30 集，上线首批 10–15 集，每周人工增加 2–3 集。

### 筛选评分表（100 分）

| 维度 | 权重 | 合格标准 |
|---|---:|---|
| transcript 质量 | 30 | 官方稿优先；与音频基本一致，可句级对齐 |
| 语速/清晰度 | 20 | A2 约 90–120 WPM，B1 110–150，B2 140–180；少重叠说话 |
| 时长 | 15 | 首选 5–12 分钟；最长不超过 20 分钟 |
| 学习价值 | 15 | 高频词/表达密度适中，语境完整 |
| 主题 | 10 | 日常、文化、职场、科技等可持续主题 |
| 授权与稳定性 | 10 | 来源清晰、音频 URL 稳定、使用方式可接受 |

低于 75 分不上架。即使热门，存在大量多人抢话、音乐背景过强、机器稿错误多或内容时效极短，也不选。

### 内容审核流程

```text
候选登记
→ 权利/来源检查（不通过即淘汰）
→ 下载元数据或登记远端音频 URL
→ 获得/生成初稿 transcript
→ 人工校对英文与断句
→ 句级时间轴对齐
→ 中文翻译初稿 + 人工抽检/修订
→ 标注难度、主题、学习理由
→ 真机试听：跳转、点词、句尾对齐
→ review → published
```

硬性 QA：首尾无截断；所有句时间递增且不重叠异常；专有名词正确；敏感/成人/政治高风险内容人工复核；节目和版权归属展示清晰。

## 7.2 第二阶段：RSS 半自动获取

- Python 定时读取白名单 RSS，以 `guid` 幂等入库；
- 新单集只进入 `draft`，绝不自动发布；
- 自动提取标题、日期、时长、封面、音频 URL；
- 若官方 transcript 可解析则抓取，否则进入“缺字幕”队列；
- 自动跑时长/语速/音质/敏感词初筛；
- 人工完成字幕、翻译、难度和版权终审后发布。

# 八、技术实现建议

## 8.1 iOS 前端

### 页面结构

建议逐步从当前 `ContentView` 大型状态机拆为：

```text
AppRootView
├─ AuthFlow
├─ LanguageGateView
├─ EnglishRootTabView
│  ├─ TodayView
│  ├─ CuratedEpisodesView
│  ├─ VocabularyView
│  └─ ProfileView
└─ GermanLegacyFlow

EpisodePlayerFeature
├─ EpisodePlayerView
├─ TranscriptView
├─ WordLookupSheet
└─ EpisodePlayerStore/ViewModel
```

不要求引入大型架构框架；用 `ObservableObject`/`@Observable`、Repository 和明确的 feature 边界即可。

### 播放器

- 用 `AVPlayer` 播放远端音频；现有 `AudioPlayerManager` 偏向词条/TTS 队列，不建议强行承载长音频。
- 设置 `AVAudioSession` 为 `.playback`，支持后台播放。
- 用 `addPeriodicTimeObserver`（约 0.2–0.5 秒）二分查找当前 `Sentence`。
- 使用 `MPNowPlayingInfoCenter`、`MPRemoteCommandCenter` 支持锁屏播放/暂停/跳转。
- 监听中断、耳机拔出、网络失败；进度每 10–15 秒及退出时落盘，避免频繁写库。
- 字幕分页/懒加载；MVP 单集短，可整集加载并本地缓存 JSON。
- 原句回放在同一 `AVPlayerItem` 上 seek 并在 `audio_end_ms` 暂停，避免生成大量音频切片。

### 数据层

- `PodcastRepository`：节目/单集/字幕读取与缓存。
- `FavoriteWordRepository`：本地乐观更新，后台 Supabase 同步。
- `EpisodeProgressRepository`：本地即时保存 + 节流云同步。
- 内容以 Supabase PostgREST 提供；封面用缓存图片组件。

## 8.2 后台与内容管线

- Supabase Postgres：元数据、字幕、收藏、进度与 RLS。
- Supabase Storage：仅存有明确托管权利的封面/音频；否则保存官方稳定 URL。
- Python CLI：`ingest_rss.py`、`import_transcript.py`、`validate_episode.py`、`publish_episode.py`。
- 字幕源文件建议保留 WebVTT/SRT；导入时标准化为 `sentences`。
- MVP 不建独立服务器；推荐逻辑用 `status + sort_order + level` 查询即可。
- 每次字幕发布增加 `transcript_version`，客户端按版本清缓存。

## 8.3 AI 能力取舍

### 第一版可加入（后台辅助，必须人工审核）

- transcript 断句与句级时间轴初稿；
- 中文翻译初稿；
- CEFR 难度、主题和学习理由候选；
- 词形还原与语境义项候选；
- 内容 QA：漏句、时间轴异常、专名不一致提示。

AI 不直接面对用户，不把未审核生成内容作为事实展示。

### 延后

- AI 老师/聊天、实时问答；
- 用户任意内容自动转录；
- 个性化讲解、语法分析、开放式口语评分；
- 全自动发布和黑盒推荐。

# 十、PRD 简版

## 10.1 产品目标

在现有声音单词 App 内新增英语 Podcast 输入方式，让用户从真实语境发现并收藏生词，次日通过原句原声复习，并回到节目验证听懂。

## 10.2 目标用户

- 大致 A2–B2、能阅读基础英文但真实听力跟不上的成人学习者；
- 每日可投入 5–15 分钟；
- 不愿制定复杂计划，希望利用通勤/碎片时间学习。

非目标用户：零基础、追求完整播客订阅体验、需要考试课程或实时口语陪练的人。

## 10.3 核心场景与用户故事

- 作为学习者，我想快速选到符合水平的短节目，以便立刻开始听。
- 当我没听懂一个词时，我想在当前字幕中点开解释，而不用跳出 App。
- 我想收藏这个词连同原句和原声，以便以后记得它出现的情境。
- 第二天我想先听原声再看答案，以验证自己是否真的听懂。
- 复习后我想回到节目原位置，以获得进步的确认感。

## 10.4 核心指标

### 北极星指标

**每周完成至少 3 次“听 ≥10 分钟，并至少收藏或复习 1 个语境词”的活跃用户数（WCL：Weekly Closed-loop Learners）。**

### 漏斗指标

| 环节 | 指标 | MVP 建议观察线，不作为承诺 |
|---|---|---:|
| 启动 | 新用户 24h 内开始首集比例 | ≥ 60% |
| 收听 | 开始后累计有效收听 ≥10 分钟比例 | ≥ 35% |
| 遇/收 | 听众点词率 / 点词后收藏率 | ≥ 30% / ≥ 25% |
| 复习 | 有收藏用户次日打开复习比例 | ≥ 20% |
| 回听 | 完成复习后回到原节目比例 | ≥ 15% |
| 留存 | 使用 Podcast 用户 D7 留存 | 与原产品基线对比提升 |

“有效收听”排除拖动跳过和后台静音异常，可用播放时间增量近似；样本过小时看趋势和访谈，不机械追阈值。

### 建议埋点

`home_view`、`episode_impression`、`episode_play_start`、`episode_listen_10m`、`transcript_word_tap`、`word_sheet_view`、`word_favorite`、`source_audio_play`、`review_start`、`review_answer`、`review_complete`、`return_to_episode`。

公共属性：`user_id/anonymous_id`、`episode_id`、`level`、`source_page`、`position_ms`、`study_language`。

## 10.5 验收标准

- English 用户可从首页在 2 次点击内开始推荐单集；Deutsch 用户看不到 Podcast。
- 播放、后台、锁屏、耳机中断和进度恢复基本可用。
- 当前字幕句与音频误差在人工 QA 后主观可接受，目标 P95 ≤ 800ms。
- 任一可点单词可在 500ms 缓存命中/2s 网络条件内打开词卡；无词条时有兜底。
- 收藏后在“我的单词”可看到原句、来源和原声，并能返回准确时间点。
- 次日队列能够识别昨日 Podcast 收藏并完成一轮复习。
- RLS 保证用户只能读写自己的收藏和进度。

# 十一、UI 设计规范

延续现有深色界面，避免为 Podcast 新建另一套品牌视觉。

## 11.1 设计基调

- 关键词：安静、专注、声音感、轻学习。
- 背景：近黑 `#000000`；一级面板可沿用约 `#121A2B`。
- 品牌强调色建议新增柔和青绿 `#70E1C2`，表达“听懂/进行中”；收藏使用暖黄 `#FFD66B`。
- 正文白 `#F7F8FA`；次级文字 `#98A6BA`；分割/描边 `#2B3D5C`。
- 成功不能只靠绿色，配合勾选与文案。

## 11.2 字体层级（Dynamic Type 必须支持）

| 用途 | 建议 |
|---|---|
| 大标题 | 28pt / Bold |
| 页面标题 | 22pt / Semibold |
| 卡片标题 | 17pt / Semibold |
| 英文字幕当前句 | 20pt / Medium，行高约 1.45 |
| 中文句译 | 15pt / Regular |
| 正文/按钮 | 16–17pt |
| 标签/辅助信息 | 12–13pt |

英文字幕不能因可点击而变成密集蓝色链接；只有触摸态短暂高亮单词。

## 11.3 栅格与组件

- 页面水平边距 20pt；8pt 基础间距系统。
- 卡片圆角 16pt；底部词卡顶部圆角 24pt。
- 主要点击区域至少 44×44pt；主按钮高度 52–56pt。
- Episode 卡统一 88pt 封面；首页 Hero 封面可 120–144pt。
- 动效 180–240ms；遵循 Reduce Motion。
- 加载使用骨架；失败就地重试；收藏采用乐观反馈，失败后回滚并轻提示。

## 11.4 无障碍

- 支持 VoiceOver：字幕句作为整体可读，单词另提供“查询此词”动作。
- 颜色对比满足 WCAG AA；当前句使用颜色 + 边线双提示。
- 支持 Dynamic Type 至少到辅助功能前两档；播放控制不因放大被截断。
- 所有音频操作有文本标签，触觉反馈不作为唯一反馈。

### 第 7 周：可靠性与无障碍

- 弱网、音频中断、缓存、错误恢复。
- Dynamic Type/VoiceOver/性能修复。

### 第 8 周：TestFlight 验证

- 招募 20–30 名 A2–B2 用户，连续使用 7 天。
- 每周至少访谈 5 人，观察点词是否自然、复习是否有“听懂”感。
- 只修 P0 阻塞，不临时加入社区/AI 对话等功能。

阶段决策：若用户很少点词，检查内容难度和词点击可发现性；若收藏多但不复习，优化首页提醒与复习长度；若复习后不回听，缩短回听路径并强化结果反馈。

## 第 3 月：收敛、上线与决定 V2

### 第 9 周：按数据修核心漏斗

- 修复首播、10 分钟完成、收藏和次日复习中的最大断点。
- 将复习控制在 3–5 分钟内。

### 第 10 周：内容管线提效

- Python 导入/校验脚本稳定化。
- 内容扩至 15–20 集，但保持质量优先。

### 第 11 周：上线准备

- 隐私说明、版权归属、崩溃监控、数据库备份与回滚。
- App Store 文案、截图、最终回归。

### 第 12 周：发布与 V2 决策

- 分阶段发布，观察 7 天关键漏斗和崩溃率。
- 基于行为数据 + 访谈决定：继续优化闭环、进入 RSS/V2，或调整内容难度与目标用户。

三个月成功信号不是内容数，而是出现一批用户稳定完成：**每天听约 10 分钟 → 收藏真实生词 → 次日听原声复习 → 回到节目听懂。**
