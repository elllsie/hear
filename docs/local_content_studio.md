# 听会儿本地内容工作室

统一管理词书、音频、复核标记、播客与文章 AI 总结。只在本机运行，浏览器访问地址默认为 `http://127.0.0.1:8765`。

## 启动与登录

在项目根目录双击 **启动内容管理台.command**。脚本使用已有的 `backend/.venv`，启动后台并打开浏览器。第一次会显示随机管理密码，请保存；之后也可在“设置与连接”修改。启动链接包含一个 5 分钟内有效、只能使用一次的登录凭证，网页读取后会立即从地址栏移除。

终端方式（在项目根目录）：

```bash
backend/.venv/bin/python -B -m backend.local_admin.server --open
```

关闭网页不会停止任务，保持启动终端运行即可。按 `Control+C` 停止后台。停止时会结束正在执行的脚本；意外中断后，下次启动会把运行中的任务标记为中断，不会自动重做线上写入。

忘记密码时，先停止后台，再运行：

```bash
backend/.venv/bin/python -B -m backend.local_admin.server --reset-password --open
```

端口被其他程序占用时可加 `--port 8766`。请通过 `127.0.0.1` 访问，`localhost` 和其他 Host 不被接受。

## 词书与音频

1. 选择词书，按单词、释义或 ID 搜索。
2. 选择音频类型：单词发音、中文释义、英文释义。
3. 试听本地或实时获取线上文件。二者可能不同，“本地未找到”不代表线上缺失。
4. 标记问题，或选择多条词条进行波形检查。
5. 单条或批量重新生成（每批最多 100 条）。Kokoro 默认语速 0.85，补齐句尾；中文释义使用 Edge 或 gTTS。
6. 在任务结果中对比旧版和新版。选中满意的结果，点击“发布选中音频”。
7. 发布会先备份旧音频，再上传并校验内容哈希，成功后同步本地正式文件。没有旧文件的首次发布没有音频回滚版本。

“恢复发布前版本”会检查线上音频是否仍为该次发布的文件，避免覆盖后来发布的新版本。部分失败的批次也会保留已取得的旧文件备份，任务中可发起恢复。批量发布逐条执行，不是数据库事务；任务失败时应检查日志确认已完成哪些条目。

App 的现有音频缓存约每小时刷新一次，需要联网再次播放。后台“线上试听”使用独立刷新参数，可立即检查刚发布的文件。

自动检查覆盖 MP3 解码、静音、发声长度和尾部留白，会将异常加入待复核。它不能判断所有音素是否读对，也不能代替人工试听。问题解决后请在“待复核”标记已解决。

## 编辑、新增与发布词书

- 编辑现有词条只保存到本地草稿，不修改内置 JSON。含本地草稿的词书会在页面标明。
- “新增词书”支持 JSON 数组文件，最大 25 MB；先校验并预览，再保存。不允许用已存在的词书 ID 覆盖整本词书。
- 每条至少包含 `id` 和 `text`。可先导出现有词书作为模板。
- 词书 ID 用字母、数字、下划线或连字符；单词 ID 必须唯一。

```json
[
  {
    "id": "1",
    "text": "example",
    "phonetic": "/ɪɡˈzæmpəl/",
    "meaningZh": "n. 例子；榜样",
    "meaningEn": "n. something that illustrates a general rule",
    "exampleEn": "Let me give you an example.",
    "exampleZh": "让我给你举个例子。"
  }
]
```

德语词条可添加 `article` 字段。新增词书同样可以搜索、生成发音和发布。

发布前建议先生成所需音频，再发布词书。词条拼写、释义的变更可能改变音频路径；生成后如果再次编辑，后台会拒绝发布过期音频草稿。发布词书时，后台创建独立版本文件并更新 `word_books` 目录，保存此前目录记录；可以从发布任务恢复之前的目录。

首次使用远端词书需要已经执行 `supabase/sql/word_books_remote_catalog.sql`，且 App 已支持远端目录。后台不自动执行 SQL，也不会替你构建或更新 App。详见 [后端内容更新说明](backend_content_updates.md)。

## 播客管理

第一次访问时从 `backend/config/rss_sources.json` 复制来源到本地状态目录。之后新增来源保存在管理台自己的 `sources.json`；不会改写原配置文件。原配置日后发生的变化不会自动合并到管理台。

建议流程：

1. 添加来源 → 预览 RSS（只读）。
2. 同步元数据 → 检查音频。
3. 优先导入 RSS 中的 VTT/SRT 时间轴字幕；没有可用字幕时生成本地转写。
4. 逐句翻译 → AI 总结 → 校验节目（包括中文完整性）。
5. 读取线上节目，检查逐句文本与 AI 总结。
6. 在来源发布状态中确认来源可用于 App，再逐集发布通过检查的节目。

除 RSS 预览外，播客流程复用现有脚本，会直接写入 Supabase 的处理中间状态、转写、译文和总结；页面在操作前明确提示。它们没有独立的本地审核草稿层。不要对已发布节目勾选“重做已有内容”，除非确实要替换现有内容。

批次数量上限 20 集。不同脚本的选择范围沿用原规则：转写检查最新单集窗口；翻译处理待翻译单集；AI 总结处理有就绪转写的单集。不勾选重做时保留现有内容。来源里已有的转写语言和模型设置会继续使用。

发布只作用于选中的单集，重新检查音频状态、逐句时序、中文译文、质量状态及来源状态，不自动批准来源，也不批量发布其他节目。初版没有接入音频镜像、官方网页/PDF 转写适配器或播客撤回功能；这些仍可使用原脚本。

## 文章与 AI

粘贴正文（20–60000 字）并保存，再生成中英文总结、要点和重点词汇。生成前提示将文本发送给已有配置的 AI 服务；结果保存在本地，可编辑、导出，不会自动发布到 App。AI 模型、提供商和地址沿用 `backend/.env`，页面只显示连接是否就绪和模型名称。

文章 AI 每次处理 1 篇；初版不估算费用，也不显示未经验证的价格。播客与文章 AI 都可能产生提供商调用费用。

## 本地数据、登录和密钥

所有管理台状态保存在 `backend/.admin/`（已在 `.gitignore` 排除）：

- `admin.sqlite3`：任务、标记、词书元数据、文章。
- `jobs/<任务ID>/`：日志、输入快照、生成草稿、发布前备份及检查结果。
- `books/`、`book-history/`、`article-history/`：词书草稿和修改历史。
- `credentials.json`：随机盐与 PBKDF2-SHA256 密码哈希，文件仅本机当前账号可读写。
- `sources.json`：管理台播客来源。

定期备份整个 `backend/.admin/`。没有自动清理草稿和备份，避免误删回滚依据，长期使用时需要留意磁盘空间。

服务只绑定回环地址，接口逐次检查登录；写操作校验 Origin 和 CSRF。会话 Cookie 为 HttpOnly、SameSite=Strict，有效期 12 小时，重启后失效。浏览器不能提交任意命令或文件路径；只可运行已经注册的业务动作。敏感环境变量会从任务日志中隐藏，服务密钥不会下发到页面。

本地限制不防范已控制本机账号的程序，请勿将此服务通过隧道或反向代理开放到公网。

## 开发验证

没有新增 npm 或 Python 服务依赖，HTTP 服务和队列使用 Python 标准库；业务请求复用现有 `httpx` / `python-dotenv`。音频解码检查使用已有 Kokoro 环境的 `soundfile`。

```bash
backend/.venv/bin/python -B -m unittest discover -s backend/local_admin/tests -v
node --check backend/local_admin/static/app.js
```

测试包含登录、CSRF、Host/Origin、路径限制、导入校验、乐观编辑、持久化、任务去重、备份顺序、回滚保护与 HTTP 音频分段读取。线上发布使用模拟 HTTP 验证，不会修改生产内容。

浏览器验收使用隔离临时目录，禁止线上写入，可运行真实 Kokoro 草稿生成。需要本机 Chrome 和支持原生 WebSocket 的 Node：

```bash
backend/.venv/bin/python -B -m backend.local_admin.tests.browser_fixture /private/tmp/tinghuier-browser-info.json
# 另开终端，在项目根目录执行：
node backend/local_admin/tests/browser_smoke.mjs /private/tmp/tinghuier-browser-info.json
```

验收完成后用 Control+C 停止隔离测试服务。测试不调用付费 AI，不发布音频或词书到线上。
